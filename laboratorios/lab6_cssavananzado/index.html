Preguntas

1 ¿Qué ventajas ofrecen las variables CSS sobre los valores hardcodeados?

Que las variables son más flexibles al momento de trabajar con ellas, estar codeando siempre valores puede llevarnos a incoherencias en el diseño css.

2 ¿En qu'e casos conviene declarar variables CSS fuera del selector :root?

Fuera del root cuando queramos hacer algo muy en específico con atributos que solo usaremos una vez, si no en root puede existir como una variable que usaremos siempre.

3. ¿Cómo se pueden utilizar las variables CSS para implementar un sistema de temas (como modo oscuro)?

Se definen variables genéricas en :root y luego se sobrescriben sus valores dentro de una clase (ej. .dark-theme) o un media query.

4. ¿Qué sucede cuando intentas usar una variable CSS que no ha sido declarada?

Se considera un propiedad inválida, entonces existe un valor de respaldo o la propiedad heredará el valor de su padre o volverá al valor por defecto.

5. ¿Cuál es la diferencia entre los enfoques mobile-first y desktop-first?

Que el mobile first esta enfocada en pantallas pequeñas y el Desktop va para un diseño en monitores más grandes, pero aún así puede ajustar elementos en pantallas pequeñas.

6. ¿Qué breakpoints son los más comunes y por qué?

Suelen ser 576px, 768px, 992px y 1200px. Esto porque coinciden con los dispositivos más comunes y evitan que el contenido se vea alargado, amontonado, desacomodado...

7. ¿Cómo afecta el viewport meta tag al diseño responsivo?

Es como un adaptador de la escala, porque lo que hace es que los móviles o tablets pudieran adaptarse al ancho necesario. Con el width=device=width el navegador ajusta el ancho real de la pantalla.

8. ¿Qué técnicas además de media queries existen para crear diseños responsivos?

Se usa Flexbox y CSS Grid, tienen propiedades que pueden reacomodar en automático los elementos.

9. ¿Cómo puedes identificar qué regla CSS está siendo aplicada cuando hay múltiples selectores?

En styles el navegador ordenará las reglas por especifidad. Las reglas que son tachadas son sobreescritas.

10. ¿Qué información proporciona la pestaña Computed en DevTools?

Muestra el valor real final. Muestra el Box model preciso que esta ocupando el elemento tras procesar todas las reglas.

11. ¿Cómo puedes simular diferentes dispositivos sin tener acceso físico a ellos?

En DevTools se puede acceder a el device mode, este permite elegir perfiles de dispositivos en específico para emularlos y probar las condiciones en las que los programamos.

12. ¿En qué situaciones es preferible usar Bootstrap sobre Tailwind CSS y viceversa?

Bootstrap es para algo más genérico o rápido, más para tener un diseño estándar. Tailwind CSS es mejor par tener un diseño personalizado sin forzar un estilo ya definido.

13. ¿Qué significa que Tailwind sea "utility-first"?

Significa que el desarrolloo se basa en pequeñas clases de utilidad que tienen una función, en vez de escribir CSS en archivos externos, este se puede crear directamente en HTML.

14. ¿Cómo afecta el uso de un framework CSS al tamaño final del bundle?

Existen frameworks que aumentan su tamaño con componentes no usados, pero hay framewotds como Tailwind que genera el CSS con los componentes que realmente se usan. Esto hace que los archivos finales sean más pequeños.

15. ¿Es posible combinar múltiples frameworks CSS en un mismo proyecto? ¿Por qué sí o por qué no?

Es posible pero no es lo mejor, porque pueden existir muchos conflictos con los nombres de clases, aumentando drásticamente el peso de la página o haciendo díficil su programación.
